# 창원 안심길 — Safety & Route API (Stage 2~3 프로토타입)

`changwon-safety` 저장소의 실제 데이터(CCTV/보안등/공공Wi-Fi/파출소 좌표, 어린이·노인 TOP10,
어린이집·경로당 좌표)를 읽어와서,

1. 임의의 위도/경도에 대한 안전 인프라 접근성 점수와 가장 가까운 TOP10 취약지역 정보 (`/api/safety`)
2. 출발지→도착지 최단/균형/안심우선 3가지 경로 (`/api/route`, Stage 3 신규)

를 계산합니다.

## 실행 방법

```bash
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

`data_loader.py`는 이 파일 기준 상대경로(`../../data`, 즉 저장소 루트의 `data/`)를 자동으로 찾습니다.
경로를 강제로 지정하려면 환경변수 `ANSHIMGIL_REPO_ROOT`(저장소 루트 절대경로)를 설정하세요.

`main.py`는 API(`/api/*`)뿐 아니라 `../frontend`(PWA 정적 파일)도 같은 프로세스에서 함께 서빙합니다.
그래서 `http://localhost:8000/`으로 접속하면 앱 화면이, `/api/safety` 등으로는 API가 같은 주소에서
동작합니다 — 배포 시에도 공개 주소가 하나만 있으면 됩니다(Render 배포는 저장소 루트의
`citizen-app/render.yaml` 참고).

파일 구성: `scoring.py`(안전도 계산 공용 로직) · `main.py`(FastAPI 엔드포인트 + 정적 서빙) · `routing.py`(Stage 3 라우팅 엔진)

## 엔드포인트

- `GET /api/safety?lat=35.22&lng=128.68&age_group=child|adult|senior`
  → 인프라 접근성 점수, 시설별 최근접거리/개수, 가장 가까운 TOP10까지 거리, 종합 등급(1~5)
- `GET /api/route?start_lat=&start_lng=&end_lat=&end_lng=&age_group=child|adult|senior`
  → 최단/균형/안심우선 3경로. 각 경로는 `distance_m`, `duration_min`(도보 약 4.8km/h 가정),
    `avg_risk`(0~1), `safety_label`(매우안전~매우위험), `path`(좌표 배열)를 포함.
- `GET /api/health` → 로드된 시설 데이터 개수 확인용

## 알려진 한계 (다음 단계에서 보완 필요)

1. **생활안전지도 WMS 범죄위험 API 키가 없어** 도시 전역 임의 좌표의 실제 범죄위험을 재현하지 못합니다.
   현재는 TOP10(노트북에서 이미 계산된 실좌표) 근접 여부로만 보정합니다.
   → 키가 확보되면 `nearest_top10` 근접 보정 대신, 해당 좌표의 WMS 픽셀을 실시간 조회하도록 교체.
2. CCTV(100m)/보안등(50m) 접근성 반경이 저장소 기존 로직 그대로라 상당히 좁습니다.
   그 결과 시내 중심가처럼 실제로는 안전 인프라가 있는 곳도 반경 밖이면 등급이 낮게 나올 수 있습니다.
   → 실제 배포 전 반경/등급 구간 값을 기획 의도에 맞게 다시 논의 필요.
3. 기준 밀도(75분위수)는 도시 경계 내 1,500개 무작위 표본으로 근사한 값이라 저장소의
   `analysis/vulnerability.py`가 실제 전체 격자에서 계산하는 값과 정확히 같지는 않습니다.
4. **`/api/route`는 아직 실제 도로망을 따라가지 않습니다.** 이 개발 환경(Claude 코딩 샌드박스)은
   OSM/네이버/카카오/Tmap 등 외부 지도·경로 API 서버에 네트워크로 직접 접근할 수 없어(egress 정책상
   pypi/npm/anthropic 도메인만 허용), 실제 도로 좌표를 받아올 방법이 없었습니다. 그래서 출발지~도착지
   주변에 격자(그리드)를 만들고, 그 위에서 실측 데이터 기반 위험도(보호점수 65% + 연령대별 TOP10
   근접도 35%)를 가중치로 다익스트라 최단경로를 계산하는 방식으로 임시 대체했습니다. "안심 우선" 경로가
   우회하는 지점 자체는 실데이터 기반이지만, 경로의 기하(도로를 따라가는 모양)는 근사치입니다.
   → **다음 작업(합의됨, 2026-09-24): Tmap(SK Open API) 보행자 경로 안내 API로 교체 예정.**
   자동차 전용인 네이버 Directions 5 대신, 실제 도보 경로를 반환하는 Tmap 보행자 API를 쓰기로 했습니다.
   키 발급 후 이 배포 주소(Render 등)를 Tmap 앱 등록의 "서비스 URL"로 사용하고, 발급받은 키는
   `TMAP_APP_KEY` 환경변수로 이 서비스에 등록하면 됩니다. 이 개발 샌드박스에서는 Tmap API 서버 호출
   자체가 막혀 있어 연동 코드를 직접 실행 검증하지 못하므로, 실제 배포 환경(여기 Render 등)에서
   최종 확인이 필요합니다. 그 전까지는 지금의 격자 기반 방식이 자동 폴백으로 계속 동작합니다.
5. 도착지 입력은 자유 주소 검색(지오코딩) 대신 `../frontend/data/destinations.json`(도서관·공원·
   파출소·어린이집·경로당·주요 랜드마크, 약 1,640곳)에서 선택하는 방식입니다. 랜드마크 15곳의 좌표는
   지도 API 미연동 상태에서의 근사치이며, 나머지(도서관/공원/파출소/어린이집/경로당)는 저장소·Google
   Places 실측 좌표입니다. → 실서비스 전환 시 네이버/카카오/Tmap 지오코딩 API로 자유 주소 검색 지원 필요.
